# tessel — ERP 프론트 시안

독립 ERP 제품의 첫 화면 시안입니다. Flex의 밝은 워크스페이스 구성과 간결한 내비게이션을 참고했습니다.

## 실행

Next.js 16 · TypeScript · Tailwind CSS v4 (Node 20.9 이상)

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # 프로덕션 빌드
npm test           # 거래 규칙 테스트 (vitest)
npm run typecheck
```

## 구조

- `app/` — 화면별 라우트 (`/inventory`, `/purchase`, `/documents/[id]` …). 기존 `#hash` 주소는 같은 이름의 경로가 되었고 `#approvalSettings`만 `/approval-settings`입니다.
- `lib/flow-core.ts` — 구매·입고·판매·반품·실사 거래 규칙 (기존 `flow-core.js`의 타입 버전)
- `lib/seed.ts` — 샘플 데이터와 localStorage 저장 (키 `tessel-demo-<회사>`, 예전 키 `gyeol-demo-`·`moa-demo-`도 읽어서 이전 입력 내역이 유지됩니다)
- `components/erp-provider.tsx` — 회사·상태·토스트·모달·상세 패널 컨텍스트
- `components/ui.tsx` — 버튼, 배지, 표, 탭 등 공통 UI
- `app/globals.css` — Tailwind 테마 (색상·글자 크기·반응형 기준점)
- `legacy/` — 변환 전 HTML/JS/CSS 원본 (참고용)

## 화면과 동작

- 홈, 재고, 구매, 구성원, 근무 현황, 휴가, 결재함, 설정
- 회사 전환, 목록 검색·필터, 품목 등록, 구매 요청, 휴가 신청, 승인·반려
- 구매 요청 → 승인 완료 → 발주 → 부분/전체 입고 → 재고 증가
- 내 휴가 승인 시 연차 잔여일 반영
- 회사별 샘플 입력 내역은 브라우저 localStorage에 보관

실제 ERP·Flex 계정이나 서버에는 연결하지 않습니다. 회사별 샘플 저장은 화면 시연용이며 운영 서비스의 데이터 격리를 구현한 것은 아닙니다. 입출고는 브라우저 샘플 데이터에만 반영됩니다. 제조 화면, 실제 서비스 연동, 급여·회계는 구현 범위에 포함하지 않았습니다.

디자인 참고: https://flex.team/landing/service/time-tracking

## 추가한 흐름

- 판매 주문 → 부분/전체 출고 → 재고 차감
- 입출고 이력: 품목, 창고, 관련 문서, 변동 전후 재고 확인
- 품목 코드로 거래를 연결하고 EA 정수 / kg 소수 수량 검증
- 초과 입고, 초과 출고, 재고 부족, 동일 처리 중복 반영 방지
- 기존 시안 데이터는 초기 재고로 보존하며, 기존 완료 입고를 다시 재고에 더하지 않습니다.
- 거래처·창고 마스터 편집, 재고 예약, 불량품 폐기·재검수는 후속 범위입니다.

검증: `npm test` (lib/flow-core.test.ts)

## 취소·반품·실사

- 입고 전 요청·발주 취소: 사유 보존, 재고 변동 없음
- 입출고 취소: 원본을 유지하고 반대 수량 이력을 추가, 문서 누계 복원
- 반품 이력이 있는 문서의 입출고 취소는 제한
- 구매 반품: 받은 수량 중 정상 재고에서 공급사로 반환
- 판매 반품: 출고 수량 범위 내 정상 재고 복원 또는 불량 보관 분리
- 실사 결과 등록 → 승인 대기 → 결재함 승인 → 재고 반영
- 실사 요청 후 재고가 바뀌면 반려 후 재요청 필요
- 검증: `npm test` (lib/exception-core.test.ts)

## 기준정보·다품목 문서 화면

- 기준정보 메뉴에서 품목, 거래처, 창고 목록과 상세 패널 확인
- 문서 관리에서 기존 샘플 발주 상세와 다품목 발주 예시 확인
- 품목 내역 / 관련 문서 / 처리 이력 / 메모·첨부 탭
- 다품목 문서는 화면 예시이며 재고를 변경하지 않음
- 거래처 담당자·결제 조건, 창고 담당 부서, LOT 관리 설정은 정적 예시
- 다품목 실거래 처리 및 첨부파일 업로드는 구현하지 않음

## 제품 고도화 화면 예시

- 회사 정보 / 사업장 / 모듈 / 단위·문서번호 규칙
- 역할별 권한표, 승인 절차 및 금액별 경로
- 직원 상세와 조직도, 주간 근무·휴가 캘린더, 근태 정정 상세
- 가용재고·예약 수량 및 창고 이동 화면
- BOM 구성·버전 이력, 생산 현황·생산 지시 상세
- 외부 연동 현황·매핑·오류 상세 (실제 연결 없음)
- 구매·판매 / 재고 / 근태 리포트

새 화면은 프론트 구성 예시입니다. 역할을 선택해도 실제 권한은 바뀌지 않으며, 예약·제조·통계·연동 예시는 실제 거래에 반영되지 않습니다. 기존 모듈 토글은 브라우저 시안 메뉴에만 적용됩니다.

## 협업 (flow.team 참고)

- 프로젝트 목록 · 상세(피드 / 업무 / 보드 / 간트차트), 내 업무, 메신저
- 업무 5단계: 요청 → 진행 → 피드백 → 완료, 보류 · 진행률 0~100% 연동 (완료 = 100%)
- 피드: 글 · 할일(체크리스트) · 업무 카드, 좋아요 · 댓글
- 보드에서 카드를 끌어다 놓으면 상태 변경, 간트차트는 오늘선과 진행률 표시
- 업무에 발주 문서를 연결하면 문서 상세에 ‘연결된 협업 업무’로 표시
- 메시지는 이 브라우저에만 저장되며 다른 사람에게 전송되지 않음
- 로직: `lib/collab.ts`, 검증: `lib/collab.test.ts`

## 견적 · 채권채무 · 인쇄 (이카운트 참고)

- 견적 관리: 견적서 작성 → 주문 전환(같은 조건으로 판매 주문 생성) / 거절, 유효기간 · 수주율
- 채권 · 채무: 출고 수량(반품 차감) × 단가 + 부가세 10% = 미수금, 입고 기준 미지급금
  - 결제 조건 거래일 + 30일, 연령 분석(기한 내 / 1~30 / 31~60 / 61일 이상), 거래처별 잔액
  - 수금 · 지급 처리(남은 금액 초과 불가), 입출금 내역
- 인쇄 양식: `/print/quote|statement|order/<문서번호>` — 견적서 · 거래명세서 · 발주서 (A4, PDF 저장)
- 재고 관리의 발주 제안: 안전재고 × 2 − 보유 − 입고 예정, 한 번에 구매 요청
- 모든 표 하단 ‘CSV 내려받기’ (엑셀 호환)
- 로직: `lib/finance.ts`, 검증: `lib/finance.test.ts`, `lib/seed.test.ts`
- 샘플 판매 · 견적 · 입금 데이터는 새로 시작하거나 설정 › 샘플 데이터 초기화 후에 보입니다.

## 생산 · 회계 · 급여 · 거래처별 단가

- 생산: BOM(완제품 · 반제품) → 생산 지시 → 자재 출고(부족하면 전부 거절) → 실적 등록(부분 가능) → 완료
  - 자재 부족 시 ‘부족 자재 구매 요청’, 입출고 이력에 생산 출고 · 생산 입고 기록
- 회계: 거래에서 전표를 자동 생성(저장하지 않고 매번 계산) — 판매 · 구매 · 반품 · 실사 · 생산 · 수금 · 지급 · 급여
  - 손익 요약, 시산표(차대 일치 확인), 전표 목록. 재고는 품목 기준 단가로 평가
  - 시안 시작 전 입고된 발주는 ‘기초 미지급’ 전표로 반영
- 급여: 기본급 · 수당 · 비과세 식대 → 4대보험(샘플 요율) · 원천세(간이세액 근사) → 실지급액
  - 월별 확정 시 금액을 저장하고 급여 전표 생성, 급여명세서 인쇄 `/print/payslip/<이름>?m=YYYY-MM`
- 거래처별 단가: 판매 주문 · 견적 · 구매 요청 입력 시 그 거래처의 최근 단가를 기본값으로, 기준정보 › 거래처별 단가 탭
- 로직: `lib/production.ts`, `lib/accounting.ts`, `lib/payroll.ts` · 검증: `lib/operations.test.ts`
- 보험 요율과 소득세는 시안용 근사치예요. 실제 지급 · 신고에는 그해 고시 요율과 국세청 간이세액표를 쓰세요.
