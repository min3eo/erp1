# 모아 ERP 프론트 시안

독립 ERP 제품의 첫 화면 시안입니다. Flex의 밝은 워크스페이스 구성과 간결한 내비게이션을 참고했습니다.

## 실행

`index.html`을 브라우저로 열면 바로 사용할 수 있습니다. 서버로 실행하려면 이 폴더에서 `python -m http.server 4173 --bind 127.0.0.1`을 실행한 후 http://127.0.0.1:4173 에 접속하세요.

## 화면과 동작

- 홈, 재고, 구매, 구성원, 근무 현황, 휴가, 결재함, 설정
- 회사 전환, 목록 검색·필터, 품목 등록, 구매 요청, 휴가 신청, 승인·반려
- 구매 요청 → 승인 완료 → 발주 → 부분/전체 입고 → 재고 증가
- 내 휴가 승인 시 연차 잔여일 반영
- 회사별 샘플 입력 내역은 브라우저 localStorage에 보관

실제 ERP·Flex 계정이나 서버에는 연결하지 않습니다. 회사별 샘플 저장은 화면 시연용이며 운영 서비스의 데이터 격리를 구현한 것은 아닙니다. 입출고는 브라우저 샘플 데이터에만 반영됩니다. 제조 화면, 실제 서비스 연동, 급여·회계는 구현 범위에 포함하지 않았습니다.

디자인 참고: https://flex.team/landing/service/time-tracking

## 추가한 흐름

- 판매 주문 → 부분/전체 출고 → 재고 차감
- 입출고 이력: 품목, 창고, 관련 문서, 변동 전후 재고 확인
- 품목 코드로 거래를 연결하고 EA 정수 / kg 소수 수량 검증
- 초과 입고, 초과 출고, 재고 부족, 동일 처리 중복 반영 방지
- 기존 시안 데이터는 초기 재고로 보존하며, 기존 완료 입고를 다시 재고에 더하지 않습니다.
- 거래처·창고 마스터 편집, 재고 예약, 불량품 폐기·재검수는 후속 범위입니다.

검증: `node flow-core.test.cjs`

## 취소·반품·실사

- 입고 전 요청·발주 취소: 사유 보존, 재고 변동 없음
- 입출고 취소: 원본을 유지하고 반대 수량 이력을 추가, 문서 누계 복원
- 반품 이력이 있는 문서의 입출고 취소는 제한
- 구매 반품: 받은 수량 중 정상 재고에서 공급사로 반환
- 판매 반품: 출고 수량 범위 내 정상 재고 복원 또는 불량 보관 분리
- 실사 결과 등록 → 승인 대기 → 결재함 승인 → 재고 반영
- 실사 요청 후 재고가 바뀌면 반려 후 재요청 필요
- 검증: `node exception-core.test.cjs`

## 기준정보·다품목 문서 화면

- 기준정보 메뉴에서 품목, 거래처, 창고 목록과 상세 패널 확인
- 문서 관리에서 기존 샘플 발주 상세와 다품목 발주 예시 확인
- 품목 내역 / 관련 문서 / 처리 이력 / 메모·첨부 탭
- 다품목 문서는 화면 예시이며 재고를 변경하지 않음
- 거래처 담당자·결제 조건, 창고 담당 부서, LOT 관리 설정은 정적 예시
- 다품목 실거래 처리 및 첨부파일 업로드는 구현하지 않음

## 제품 고도화 화면 예시

- 회사 정보 / 사업장 / 모듈 / 단위·문서번호 규칙
- 역할별 권한표, 승인 절차 및 금액별 경로
- 직원 상세와 조직도, 주간 근무·휴가 캘린더, 근태 정정 상세
- 가용재고·예약 수량 및 창고 이동 화면
- BOM 구성·버전 이력, 생산 현황·생산 지시 상세
- 외부 연동 현황·매핑·오류 상세 (실제 연결 없음)
- 구매·판매 / 재고 / 근태 리포트

새 화면은 프론트 구성 예시입니다. 역할을 선택해도 실제 권한은 바뀌지 않으며, 예약·제조·통계·연동 예시는 실제 거래에 반영되지 않습니다. 기존 모듈 토글은 브라우저 시안 메뉴에만 적용됩니다.
